# 《栖息邮局》毕业设计评审工作台

把场景、角色、产品、动画与特效集中排列，方便你持续提交版本，也方便指导老师在异地打开作品、检查细节并留下意见。五类作品均可按需要新增，数量不限。

**当前交付的是待部署的网站源码。尚未确认目标仓库的连接状态，也未发布上线。** 目标仓库为 [YinXiangs/BiShe_Mesh_DongHua_TeXiao](https://github.com/YinXiangs/BiShe_Mesh_DongHua_TeXiao)；成功部署后的预期地址为 [栖息邮局评审网站](https://yinxiangs.github.io/BiShe_Mesh_DongHua_TeXiao/)。

先分清两种保存方式：

| 方式 | 保存在哪里 | 老师在另一台设备能否看到 |
| --- | --- | --- |
| 本机草稿 | 当前浏览器的本地数据库 | 不能。清除浏览器数据也可能丢失草稿，请下载版本备份 |
| 共享评审 | 你配置的 Supabase 私有存储与数据库 | 可以。需要先上传，再生成完整评审链接 |

GitHub Pages 负责托管网页；共享文件与意见由 Supabase 保存。本机草稿不会自动变成共享提交。首页出现的演示作品只是体验示例，不代表你已经上传了模型。

## 第一步：开通共享评审

按 [共享评审配置说明](supabase/README.md) 完成一次初始化：创建 Supabase 项目，执行数据库脚本，添加自己的所有者邮箱，部署 `review-share` 分享函数，并设置邮箱登录返回地址。

记下 **项目地址** 和 **公开 publishable key／legacy anon key**，下一步会用到。学生通过邮箱里的登录链接进入自己的工作台；老师通过专属评审链接查看和留言，**不需要 GitHub 账户，也不需要登录网站**。

配置中的私有文件桶应保持 Private。`secret` 或 `service_role` 密钥只能用于服务端，不能填进网页、仓库或前端构建变量。具体权限与操作步骤均在上述说明内。

## 第二步：把网站发布到 GitHub

1. 用 GitHub Desktop 克隆目标仓库。若仓库已有内容，先保留原文件，再合并本次网站源码。
2. 把本项目的**源码内容放到该仓库根目录**：根目录应直接看到 `package.json`、`index.html`、`src`、`public`、`supabase` 和 `.github`。不要再套一层 `qixi-post-review` 或 `sites` 文件夹。不要复制 `node_modules`、`dist`、真实模型、视频或私有密钥。
3. 在仓库网页打开 **Settings → Secrets and variables → Actions → Variables**，新建两个 Repository variables：

   | 名称 | 填写内容 |
   | --- | --- |
   | `PUBLIC_SUPABASE_URL` | 自己的 Supabase 项目地址 |
   | `PUBLIC_SUPABASE_ANON_KEY` | 公开 publishable key／legacy anon key |

4. 在 **Settings → Pages → Build and deployment → Source** 选择 **GitHub Actions**。
5. 回到 GitHub Desktop，将源码提交到 `main` 分支并 **Push origin**。仓库 **Actions** 页面中的 `Publish review website` 会自动测试、构建并部署；也可以手动运行该工作流。

等部署任务全部成功后，再打开预期网站地址。以后修改网站源码，继续提交并推送即可更新网页。修改上面的 Variables 后，也需要重新运行部署。

## 第三步：提交真实作品，发送老师评审链接

1. 打开网站的“连接与账户”，用第一步配置的所有者邮箱发送并打开登录邮件，进入“共享评审”。
2. 点击“新增作品”，选择分类并填写名称。进入作品后点“提交新版本”：场景、角色、产品、游戏动画均选择 **一个 FBX 和它的全部外部贴图**；游戏特效选择 **一个 MP4**。等待保存成功，再刷新确认版本仍在。
3. 点击“邀请老师评审”，或在某件作品里生成评审链接。把**完整链接**发送给老师，包括地址末尾的 `#review=…` 部分。只发首页地址无法访问你的私有作品。
4. 老师打开作品，旋转查看模型或播放视频，填写称呼、检查维度、建议与意见。意见会绑定当前版本，并记录模型视角或视频时间点；“定位检查位置”可以回到相应位置。
5. 修改作品后提交新版本。旧文件和对应意见会保留，便于对照；“下载版本”可将该版本原始文件打包为 ZIP 备份。

分享前请用另一台设备或无痕窗口完整检查一次：确认模型、贴图、视频和意见都能读取，留言后刷新双方页面仍可看到。**必须用你的真实 FBX／MP4 联测；演示几何体、自动化测试或本机预览不能代替这一步。**

拿到完整分享链接的人可以在其有效范围内查看、下载和署名留言，请只发给需要评审的人。访客称呼由对方自行填写，未经账户验证；“建议通过”不会自动改变你的作品进度。链接可以设置有效期并撤销，详细规则见 [共享评审说明](supabase/README.md#分享范围与失效规则)。

## 功能核对

| 检查内容 | 已提供的功能 |
| --- | --- |
| 项目目录 | 五类作品、搜索、进度筛选、制作中／待检查／待修改／已通过 |
| FBX 模型 | 旋转、平移、缩放，三角面数、缓冲顶点数、材质与贴图列表 |
| 模型结构 | 实际节点层级、节点显示开关、线框、法向着色、静态法向箭头、骨架 |
| FBX 动画 | 实际动画片段选择、播放暂停、时间轴、速度调整 |
| MP4 特效 | 视频播放、时间点留言与回看 |
| 版本与意见 | 历史版本、原文件 ZIP 下载、按版本保存反馈、视角／时间点定位 |

三角面数是 FBX 导入浏览器后三角化的数量；缓冲顶点可能因 UV 或法向分裂，与建模软件里的原始顶点数不同。FBX 材质是浏览器近似显示，复杂 UE 材质建议同时保留效果截图。蒙皮动画可用法向着色检查，法向箭头只用于静态网格；动画 FBX 应包含匹配的角色网格与骨架。

## 文件与保存提醒

- 每个版本默认单文件不超过 **200 MiB**，全部文件合计不超过 **300 MiB**；云端还受自己的 Supabase 套餐、全局设置和存储桶限制。此版本暂未提供断点续传，大文件请在网络稳定时提交。
- FBX 与外部贴图应一起选择；不要提交不同目录下的同名贴图，避免材质错配。MP4 推荐使用浏览器常见的 H.264／AAC 编码。
- **模型、贴图和视频通过网站上传，不要放进 GitHub 源码仓库。** GitHub 网页添加文件上限为 25 MiB，普通 Git 推送超过 100 MiB 的单文件会被拒绝；Git LFS 也不能直接用于 GitHub Pages。[GitHub 文件限制](https://docs.github.com/en/repositories/working-with-files/managing-large-files/about-large-files-on-github)、[Git LFS 与 Pages](https://docs.github.com/en/repositories/working-with-files/managing-large-files/about-git-large-file-storage)
- 无论使用本机草稿还是共享评审，都请保留自己的工程源文件，并定期下载版本备份。

## 本机预览源码

如需先检查网页，在项目根目录安装 Node.js 22 或更新版本后运行：

```sh
npm ci
npm run dev
```

打开终端显示的本地地址。`npm test` 运行检查，`npm run build` 生成可部署网页。共享评审仍需完成第一步的云端配置。
