# 《栖息邮局》毕业设计评审工作台

访问：[栖息邮局作品工作台](https://yinxiangs.github.io/BiShe_Mesh_DongHua_TeXiao/)。手机 QQ、微信和电脑使用同一个网址，登录后读取同一份作品、版本、检查状态与留言。

## 学生提交作品

1. 输入学生访问密码进入网站；密码不在页面公开显示。
2. 点击“新增作品”，选择场景建模、角色建模、产品建模、游戏动画或游戏特效，填写作品名称。
3. 点击“提交新版本”。模型选择 1–4 张 JPG／PNG 三视图或细节图；动画和特效选择 1 个 MP4，可另附最多 4 张图片。图片等比留边到 1920×1080，不拉伸。
4. 如需老师下载原件，可附加 1 个 FBX；也可勾选沿用此作品已有版本的 FBX，避免重复上传。
5. 直接把网站网址发给老师。修改作品后提交新版本，旧文件和对应意见继续保留。

学生可以新增、编辑、删除和恢复作品，不能设置老师的检查结果。新版本会重新显示“待检查／老师未读”。同一文件名可用于不同版本，同一版本内不能有重名贴图。

## 老师查看和反馈

输入教师访问密码进入网站，无须注册 GitHub 或其他账户。打开作品通过上一张、下一张、页码或左右滑动检查图片；MP4 点击后加载播放。老师可以对最新版本设置“待检查”“待修改”或“已通过”，并留下意见。状态和留言保存到服务器，其他设备刷新后也能看到；网站在可见时每 30 秒自动更新列表。

检查面板中的“刷新反馈”保留当前图片页码、视频位置和未提交的意见。留言可定位对应图片或视频时间。“导出评审记录”可下载 TXT／JSON 备份；“下载 FBX”仅在点击时读取附件并交给浏览器下载，目录、详情和视频预览都不请求 FBX。

## 原设备上的旧作品

旧版网站曾把数据保存在使用它的浏览器里。请在原来上传过作品的手机 QQ 或电脑浏览器打开相同网址，用学生身份登录，点击“迁移这台设备上的旧作品”。勾选需要的作品并开始迁移，保持页面打开。原文件和记录会保留；中断后可以重试，已完成版本会跳过。

如果还要迁移老师之前留下的通过状态和留言，勾选“同时迁移老师反馈”，由教师访问密码确认。云端已有新的评审时不会用旧结果覆盖。如果云端已有不同的新版本，则停止追加该作品的旧版本，保留两边记录。

完成一次迁移后，老师在自己的手机登录同一网址即可看到，不必重复上传。迁移必须在存有原数据的那个浏览器进行；电脑无法直接读取手机 QQ 的本机数据。

## 文件和预览

- 单文件最多 200 MiB，每个版本总计最多 300 MiB。新提交最多 4 张 JPG／PNG、1 个 MP4、1 个可选 FBX；模型类别不接收 MP4。采用 5 MiB 分片上传。
- 图片提交顺序就是检查页序；尺寸统一为 1920×1080。动画和特效视频推荐 H.264／AAC 的 MP4。
- 每张图片另生成 1920×1080 的轻量 JPG 评审图（最多 512 KiB），独立保存，原 JPG／PNG 保留。打开作品先显示已有封面，再加载当前页的评审图；点击“查看原图”才下载原始图片。旧版本尚无评审图时回退到原图。快速图上传未完成会提示，已经提交的作品不会因此丢失。
- 本次登录中已经下载的评审图保留在最多 8 MiB 的内存缓存里，关闭再打开作品可复用；退出、登录失效或刷新网页后清除。翻页不预载其余图片、MP4 或 FBX。
- 模型结构、法向、线框与 UE 三渲二效果通过提交截图展示，网站不再下载或解析 FBX 来生成缩略图、预览或面数。已有历史三角面记录仍可显示。
- 旧 FBX／贴图版本和留言保留；已有封面直接读取，无封面时提示补充图片。可给旧作品提交图片新版本并沿用其 FBX。
- 请自行保留工程文件。模型、贴图和视频通过网站上传，不放进 GitHub 源码仓库。

## 维护与发布

前端由 GitHub Pages 托管。服务器使用独立的共享数据库和文件库，登录与教师／学生操作权限在服务器检查。前端仅包含公开服务地址，不包含服务端凭据。连接失败时显示错误，不再切换到本机保存或把失败当作空目录。

共享服务现通过 `https://qixi-access-gateway.onrender.com` 访问。这个入口已在老师原先无法连接的网络上通过检测，转发到同一份数据库与文件库，不另建或复制作品。Render 免费实例闲置后可能需要约一分钟启动，并受流量等限制；不代表无限免费用量。连接时请等待页面返回结果。

`public/shared-config.json` 保存默认共享服务地址；`scripts/write-config.mjs` 在构建时写入公开的 `public/config.json`。可用构建变量 `PUBLIC_API_URL` 指向已部署的兼容服务。原 Supabase 文件仅作为历史源码保留，当前入口不再使用该连接方式。

本地安装 Node.js 22 或更新版本后：

```sh
npm ci
node scripts/write-config.mjs
npm run dev
```

`npm test` 运行功能检查，`npm run build` 构建网页。推送 `main` 后，`.github/workflows/pages.yml` 自动测试、构建并发布；仓库 Pages 的来源保持 GitHub Actions。
