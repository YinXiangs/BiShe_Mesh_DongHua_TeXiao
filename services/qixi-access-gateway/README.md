# 栖息邮局备用访问入口

这是原共享后台的固定入口转发服务，用来测试替代域名能否让老师访问。模型、贴图、版本、留言继续保存在原来的 D1 / R2 中；此服务不在主机磁盘保存作品，也不另建资料库。

已部署到 `https://qixi-access-gateway.onrender.com`，采用新加坡 Free 实例。本地 12 项检查通过；公网已验证约 6 MiB 模型分片上传、下载字节一致性、范围请求、三份独立登录之间的已读／审批／留言同步、权限及历史版本。用户已确认老师原先无法访问的设备能打开 `/api/health`，显示 `ok:true` 和 `storageReady:true`；也已确认通过原 GitHub 网站能够登录并查看作品。

## 运行与验证

需要 Node.js 22 或以上，无第三方依赖。进入此文件夹运行 `npm test`，启动使用 `npm start`。平台通过 `PORT` 指定端口（默认 3000）。`GET /health` 只检测这个入口自身，正常返回 `ok: true`；`GET /api/health` 才会转发到现有共享后台，部署后必须同时测试两者，再实际验证教师登录、跨设备读取和上传分块。

正式服务固定连接原来的 `https://qixi-post-review-shared-yinxiangs.sharp-root-9607.chatgpt.site`，没有环境变量或请求参数可以更换上游。代码中的测试工厂仅接受本机 HTTP 模拟服务器。

## 访问限制

- 只转发既有 `/api` 接口；拒绝其他路径、编码路径、路径穿越和不匹配的方法，不提供任意网址代理。
- 图片轻量预览使用 `GET /api/files/:id/preview`，学生上传派生预览使用同一路径的 `PUT`；原文件下载接口保持不变。角色、文件类型和归属仍由原后台校验，预览沿用同样的鉴权头与流式传输限制。
- 只允许 `https://yinxiangs.github.io` 跨域访问。没有 Origin 的直接连接检测或持有效凭据的客户端也可连接；最终权限仍由原后台校验。
- 传递原始访问令牌，不生成后台绕过令牌，不设置或传递 Cookie；不记录访问密码、令牌或请求内容。不转发客户端 IP 头以伪造独立用户身份。
- 文件采用流式传输，每个上传请求最多 6 MiB，配合现有 5 MiB 上传分块。文件总大小和权限继续由原后台控制。
- 原样传回上游状态和允许的响应头，绝不跟随重定向，也不转发 `Location` 或 `Set-Cookie`。若上游拦截服务器请求，此入口仍然不可用，必须实测。
- 上游的密码错误限制按连接 IP 计算。经过入口后，多名用户可能共用出口 IP，累计密码错误可能让大家暂时无法登录（现有规则为 15 分钟内 5 次失败）。本服务不削弱此限制。

## 免费主机的使用边界

Render 免费实例可能休眠，第一次访问需要等待启动，另有带宽和外部流量限制，大量转发外部文件可能被暂停。不能把它视为 300 个模型的稳定生产容量保证，也不能承诺永久免费或无限流量。账号已连接，服务已部署，GitHub 网站通过公开配置使用此入口。
